## How it runs now (unattended, on AWS)

- `00_GLOSSARY_PIPELINE_CORE/scripts/run_pipeline.py` is the whole orchestrator (resumable; skips stages gated PASS on disk). `deploy/supervisor.py` wraps it under systemd (`deploy/install_service.sh`): stall watchdog, a triage agent that auto-restarts only transient failures and writes proposed fixes (never applied), SNS emails.
- Generic stages run on a Bedrock tool-using agent (`bedrock_agent.py`); stages 08 and 11 have cheaper dedicated scripts (`glm_generate.py`, `bedrock_reconcile.py`, `bedrock_evaluate.py`).
- Model ladders per role fall back on daily-quota errors and re-probe the top model hourly (`GEN_LADDER`, `EVAL_LADDER`, `QUOTA_COOLDOWN_H`). Spend is capped by `MAX_USD` against the shared cost log. `deploy/status.sh` prints progress; `deploy/aws_budget_alarms.sh` sets $500/$700/$1000 alerts.
- Bedrock account limits found: requests per minute set to 5 (default 10,000) for the Claude models; daily token quotas exhausted on Opus 4.6/4.5; GLM 5.3 and the OpenAI GPT-5.x/6.x models return AccessDenied. A quota request and an AWS Support case were opened; check their status before the next batch.

## Known limits and open items

- Multi-path batches need a hand-written `chunks.json`.
- A blocking stage 13 leakage result stops the run for a human instead of routing the fix back to stage 05/09/11.
- `orchestrator_notes.md` has the history, lessons and the ~20 TOC conflicts to fix upstream. Optional-enrichment fact ids (e.g. `f6` on `python.lists`) are cited by teaching blocks but live only in the coverage briefs.
- Stage 07 (YouTube transcript fetching) was only done for this batch; fetching from an AWS IP may hit 429s on a new batch.
- New batches need their frozen TOC workspaces (outside this repo) on the machine that runs them.
