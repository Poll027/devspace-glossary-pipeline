This document explains how to permanently delete a Compute Engine instance.
If you no longer need a compute instance, then delete it to stop incurring
charges for the compute instance and its attached resources. You can't recover
the deleted compute instance. To learn more about the states that a compute
instance goes through from its creation up to its deletion, see
Compute Engine instance lifecycle.
Caution: If you delete a compute instance in a managed instance group (MIG) with
an autoscaler, then the MIG might automatically create a new compute instance to
replace the deleted compute instance. To prevent this behavior,
resize the MIG
or reconfigure its autoscaler.
Billing implications for deleted instances
After you delete a compute instance, you stop incurring charges for the compute
instance and its attached resources, except in the following cases:
If you delete a compute instance that is hosted on a
sole-tenant node, then you still incur charges for
the sole-tenant node.
If you delete a compute instance that you created by using a
reservation, then you
continue to pay for the reserved resources until one of the following
occurs:
You delete the reservation, or Compute Engine does so for an
automatic operation.
You reduce the number of reserved compute instances in the reservation.
If you have a
committed use discount,
then you continue to pay for the committed resources, regardless if you use
them or not.
If you preserve any resources that are attached to the compute instance,
such as disks or external IP addresses, then you continue to pay for those
resources until you delete them.
For more information, see
VM instances pricing.

Preserve attached resources
If you want to preserve a resource that is attached to a compute instance before
you delete it, then you can do one or more of the following:
To preserve a GPU attached to an N1 virtual machine (VM) instance,
remove the GPU from the VM.
To preserve an attached disk, do one of the following:
To preserve a boot disk,
detach the boot disk from the compute instance.
To preserve a boot or non-boot disk, set the
auto-delete setting of the disk to false.
To preserve the data of a Local SSD disk, copy the data of the disk to a
persistent storage option.
To reuse the static external IP address of a compute instance,
unassign the IP address.
Required roles
      To get the permissions that
      you need to delete a compute instance,
      ask your administrator to grant you the
    Compute Instance Admin (v1)  (roles/compute.instanceAdmin.v1) IAM role on the project.
  For more information about granting roles, see Manage access to projects, folders, and organizations.

        the permissions required to delete a compute instance. To see the exact permissions that are
        required, expand the Required permissions section:

The following permissions are required to delete a compute instance:
                  compute.instances.delete

                To force the deletion of an attached disk:
                  compute.disks.delete

          these permissions
        with custom roles or
        other predefined roles.
Delete compute instances
When you delete a compute instance, Compute Engine
stops the compute instance
before it's deleted. If you delete one or more compute instances simultaneously,
then you must decide what happens to the attached disks:
Delete disks: you can delete the boot disks, non-boot disks, or all of
its attached disks to your compute instances. If you configured your disks
to be preserved upon deletion, then you can optionally override this
configuration and force their deletion.
For instructions, see
Delete compute instances and all attached resources.
Preserve disks: you can preserve boot disks, non-boot disks, or all of
its attached disks to your compute instances.
For instructions, see
Delete compute instances and preserve disks.
Delete compute instances and all attached resources
To delete compute instances in specific scenarios—such as forcing the
deletion of attached disks, skipping or ending a graceful shutdown, or deleting
multiple instances at the same time—use the appropriate method:
Force delete disks: if you've
configured an attached disk to be preserved
when Compute Engine deletes a compute instance, then you can
override this setting and force its deletion by using the Google Cloud CLI.
Caution: Forcefully deleting a disk that is attached to a compute instance
also deletes all its instant snapshots. You can't recover these snapshots.
To retain the data in an instant snapshot,
create a standard snapshot from it
before you delete the compute instance.
Skip or end a graceful shutdown: if you've enabled
graceful shutdown in
the compute instance, then you can delete the compute instance without
gracefully shutting it down or end an ongoing graceful shutdown by using the
Google Cloud console, gcloud CLI, or REST API.
Delete multiple compute instances: if you want to delete multiple
compute instances simultaneously, then use the Google Cloud console or,
for multiple compute instances that exist in the same zone, the
gcloud CLI.
To delete one or more compute instances and all of their attached resources,

// deleteInstance sends a delete request to the Compute Engine API and waits for it to complete.
func deleteInstance(w io.Writer, projectID, zone, instanceName string) error {
	// projectID := "your_project_id"
	// zone := "europe-central2-b"
	// instanceName := "your_instance_name"
	ctx := context.Background()
	instancesClient, err := compute.NewInstancesRESTClient(ctx)
	if err != nil {
		return fmt.Errorf("NewInstancesRESTClient: %w", err)
	}
	defer instancesClient.Close()
	req := &computepb.DeleteInstanceRequest{
		Project:  projectID,
		Zone:     zone,
		Instance: instanceName,
	}
	op, err := instancesClient.Delete(ctx, req)
	if err != nil {
		return fmt.Errorf("unable to delete instance: %w", err)
	}
	if err = op.Wait(ctx); err != nil {
		return fmt.Errorf("unable to wait for the operation: %w", err)
	}
	fmt.Fprintf(w, "Instance deleted\n")
	return nil
}

from __future__ import annotations
import sys
from typing import Any
from google.api_core.extended_operation import ExtendedOperation
from google.cloud import compute_v1
def wait_for_extended_operation(
    operation: ExtendedOperation, verbose_name: str = "operation", timeout: int = 300
) -> Any:
    """
    Waits for the extended (long-running) operation to complete.
    If the operation is successful, it will return its result.
    If the operation ends with an error, an exception will be raised.
    If there were any warnings during the execution of the operation
    they will be printed to sys.stderr.
    Args:
        operation: a long-running operation you want to wait on.
        verbose_name: (optional) a more verbose name of the operation,
            used only during error and warning reporting.
        timeout: how long (in seconds) to wait for operation to finish.
            If None, wait indefinitely.
    Returns:
        Whatever the operation.result() returns.
    Raises:
        This method will raise the exception received from `operation.exception()`
        or RuntimeError if there is no exception set, but there is an `error_code`
        set for the `operation`.
        In case of an operation taking longer than `timeout` seconds to complete,
        a `concurrent.futures.TimeoutError` will be raised.
    """
    result = operation.result(timeout=timeout)
    if operation.error_code:
        print(
            f"Error during {verbose_name}: [Code: {operation.error_code}]: {operation.error_message}",
            file=sys.stderr,
            flush=True,
        )
        print(f"Operation ID: {operation.name}", file=sys.stderr, flush=True)
        raise operation.exception() or RuntimeError(operation.error_message)
    if operation.warnings:
        print(f"Warnings during {verbose_name}:\n", file=sys.stderr, flush=True)
        for warning in operation.warnings:
            print(f" - {warning.code}: {warning.message}", file=sys.stderr, flush=True)
    return result

# Sends an instance deletion request to the Compute Engine API and waits for it to complete.
#
# @param [String] project project ID or project number of the Cloud project you want to use.

  # Initialize client that will be used to send requests. This client only needs to be created

  client = ::Google::Cloud::Compute::V1::Instances::Rest::Client.new
  puts "Deleting #{instance_name} from #{zone}..."

Delete compute instances and preserve disks
By default, deleting a compute instance deletes the compute instance and its
attached resources. However, when you delete a compute instance by using the
gcloud CLI, you can specify to preserve the attached disks,
regardless of their
auto-delete settings.
To delete one or more compute instances in the same zone while preserving their
attached disks, use the
gcloud compute instances delete command
with the --keep-disks flag:
gcloud compute instances delete INSTANCE_NAMES \
    --keep-disks=KEEP_DISK_TYPE \
    --zone=ZONE
Replace the following:
INSTANCE_NAMES: a list of names of compute instances that
you want to delete, separated by spaces. For example, specify
instance-01 instance-02 instance-03.
KEEP_DISK_TYPE: the types of disks that you want to
preserve. Specify one of the following values:
To preserve attached boot and non-boot persistent storage: all
To preserve only attached boot persistent storage: boot
To preserve only attached non-boot persistent storage: data
ZONE: the zone where the compute instances exist.
If you've enabled
graceful shutdown in one
or more compute instances, then you can save costs by deleting the compute
instances without gracefully shutting them down, or by manually ending an
ongoing graceful shutdown. To do so, include the --no-graceful-shutdown flag
in the command:
gcloud compute instances delete VM_NAMES \
    --keep-disks=KEEP_DISK_TYPE \
    --no-graceful-shutdown \
    --zone=ZONE
