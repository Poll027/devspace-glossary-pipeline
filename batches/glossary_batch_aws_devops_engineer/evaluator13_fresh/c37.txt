tb1: An S3 object was overwritten or simply deleted, and the lab requires an earlier version to remain recoverable. Versioning, restoration method and lifecycle expiry all affect the available recovery path.
tb2: S3 versioning retains multiple versions of an object, including versions displaced by overwrites.
tb3: In the S3 console, open the bucket’s Properties > Bucket Versioning > Edit > Enable > Save changes. Check the Bucket Versioning setting to verify it is enabled. Apply the supplied lifecycle JSON with the following command, substituting the approved bucket and policy file:

aws s3api put-bucket-lifecycle-configuration --bucket <bucket> --lifecycle-configuration file://<policy.json>

Then retrieve the configuration to verify the configured rules:

aws s3api get-bucket-lifecycle-configuration --bucket <bucket>

In a versioning-enabled bucket, a simple delete ordinarily creates a delete marker rather than removing prior versions; deleting a specified version permanently removes it.

To restore an overwritten object, copy the selected prior version to the same key to create a new current version; to undo a simple deletion, remove its delete marker to expose the preceding version.

Inspect noncurrent-version expiration and other lifecycle rules so required recoverable versions remain for the required window.
tb4: Suppose the approved bucket contains two versions of releases/orders.zip and the newer one overwrote the earlier content. Select the required prior version and copy it to the same key; that creates a new current version with the selected content. For a separate simple-deletion case, inspect the delete marker and remove that marker to expose the preceding version. These are different recovery operations, so identify the actual case before acting. Inspect noncurrent-version expiration and other supplied lifecycle rules against the required recovery window. A retained prior version is useful only while it remains available under those controls. Do not delete a specified needed version: that operation permanently removes that version.
tb5: A simple delete in a versioning-enabled bucket ordinarily creates a delete marker; it is not equivalent to permanently deleting a specified version. Keep ordinarily in the explanation, and check lifecycle rules rather than assuming versioning alone preserves every version indefinitely.
