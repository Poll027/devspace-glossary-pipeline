
### 39 aws_devops.publish_a_traceable_immutable_build_artifact
Inline: supplied build output (CodeBuild authoring not required): The build output and build-run metadata are supplied; this concept publishes and traces that output without requiring CodeBuild buildspec authoring.; supplied build output: Supplied scaffolding: the exercise provides build output. Independent creation or implementation of this input is not assumed; separately declared skills still must be mastered.; immutable digest: A content identifier linking the supplied artifact to its source revision and build record.
tb1: A release needs more than a downloadable build file: the operator must connect the exact content with its source and build provenance. Follow one supplied output through attestation, immutable publication, download and provenance verification.
tb2: An artifact attestation binds provenance such as source repository, revision and build workflow to an artifact digest.
tb3: For a supplied output file, set workflow permissions id-token: write, contents: read and attestations: write, generate provenance with actions/attest@v4 and subject-path set to the file, then publish it with actions/upload-artifact@v4 using path set to that file and name set to the supplied revision-based version; retain the workflow run, artifact name and upload’s SHA256 digest as the immutable content reference, since v4 artifacts are immutable.

Download the published artifact with actions/download-artifact, which checks the upload’s SHA256 digest and warns on mismatch, then verify the extracted output file’s provenance with gh attestation verify PATH/TO/YOUR/BUILD/ARTIFACT-BINARY -R ORGANIZATION_NAME/REPOSITORY_NAME --format json and inspect the verified attestation for the source revision and build workflow/run before deployment.
tb4: Suppose the supplied output is an orders release file for revision rev-42. Use that file as subject-path for actions/attest@v4 with the stated workflow permissions. Publish the same file through actions/upload-artifact@v4 using its path and the supplied revision-based name. Retain the workflow run, artifact name and upload SHA256 digest as the content reference. Download it through actions/download-artifact and inspect any digest-mismatch warning; that action checks the upload digest. Then run the stated gh attestation verify template on the extracted output file for the approved repository. Inspect the verified JSON attestation for source revision and build workflow/run before deployment. The example keeps download-integrity evidence and provenance evidence connected to the same output rather than treating either one alone as the entire traceability record.
tb5: A digest check and provenance verification answer different questions. Download checks the upload SHA256 digest and warns on mismatch; the verified attestation provides source and build context. Do not claim the download action itself blocks every mismatch or proves the intended source revision.
