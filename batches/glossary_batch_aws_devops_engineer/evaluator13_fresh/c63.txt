
### 63 aws_devops.diagnose_an_iam_denied_request_from_request_and_policy_evidence
Inline: supplied request evidence: Supplied scaffolding: the exercise provides request evidence. Independent creation or implementation of this input is not assumed; separately declared skills still must be mastered.; explicit deny: A matching IAM deny statement that overrides permission grants.
tb1: An AWS request was denied even though one policy appears to allow it. Diagnose the specific request and applicable constraints before widening permissions. The principal, action, resource and context are the starting evidence.
tb2: An access-denied diagnosis is specific to the requesting principal, operation, resource and request context.
tb3: Inspect the request and applicable policies for an explicit deny, missing allow or unsatisfied condition and use available denial context to localize the cause.

Resource policies, session policies, permissions boundaries and organization policies can constrain access beyond one identity policy; explicit deny takes precedence.

Make the smallest approved policy or request correction supported by the evidence and retest the denied operation.
tb4: Take the supplied denied request and write down the requesting identity, operation, target and context. Compare them with applicable policy statements and any available denial context. Locate an explicit deny, a missing applicable allow or an unsatisfied condition supported by the evidence. Do not stop after finding an allow in one identity policy: resource policies, session policies, permissions boundaries and organization policies can also constrain access. An applicable explicit deny takes precedence. Make the smallest approved request or policy correction and repeat the same operation as the test. Keep the before-and-after evidence specific to this request rather than claiming the corrected identity now has unrestricted access.
tb5: An access denial is not proof that the identity policy merely needs a broader Allow. Other policy constraints may apply, and explicit deny takes precedence. Use the request and denial evidence to choose a minimal approved correction, then retest that operation.
