tb1: A Config rule reports a noncompliant resource. Before choosing a response, establish which recorded configuration differs from the rule's desired conditions and what the governing policy permits.
tb2: AWS Config rules evaluate recorded resource configuration against desired conditions and report compliance results.
tb3: Open the rule’s noncompliant resources and inspect the affected resource, evaluation result and rule parameters to identify the configuration mismatch.

Choose the established remediation or escalation path from the governing policy rather than treating a compliance result as proof of an attack.
tb4: Open the supplied rule's noncompliant-resource result and record the resource identity. Compare the evaluation result and rule parameters with the affected resource's recorded configuration. Suppose the mismatch is a supplied setting outside the rule's required value; describe that setting mismatch rather than labeling the resource attacked. Choose the established remediation or escalation path from the governing policy. Preserve the evaluation evidence with that choice so the next operator can see why the response was selected. This is basic configuration-finding triage, not proof of malicious activity or permission to apply an unapproved change.

For a supplied noncompliant result, distinguish the rule's required value from the resource's recorded value. If the rule parameters differ from what the operator expected, include that discrepancy in triage rather than silently comparing with a different criterion. The governing policy determines whether the next action is remediation or escalation. The compliance evidence establishes a configuration mismatch, not an attacker or a cause of compromise.
tb5: A compliance result reports configuration against desired conditions; it is not proof of an attack. Read the resource, evaluation and parameters before choosing the policy-governed remediation or escalation path.
