tb4 Check the supplied runbook's preconditions before taking the first approved action. Execute only the stated approved steps and compare each actual result with its expected operational outcome before advancing. If a supplied stop condition occurs or a result falls outside the runbook's bounds, stop routine execution and escalate with the observed evidence. Record the last completed action and the result that required escalation so the next responder need not guess what happened. This example applies a known procedure safely; it does not authorize improvising further resource changes because the initial diagnosis seemed familiar.

For a passing step, record the actual result that matches the runbook before moving to the next approved action. For a failing step, preserve its output and stop/escalate according to the bounds. These branches keep the response reproducible for another operator. A runbook that initially fits the incident does not authorize continuing after its own expected-result check says the situation is outside routine execution.
