INLINE supplied topology=supplied
f1 The subnet’s route table must contain a matching destination route to a usable target for the required network path.
f2 Check DNS resolution and the intended endpoint address using the supplied tools, then inspect route association, required protocol/port rules and response traffic to localize the failing layer.
f3 Network ACLs are stateless, so required requests and responses need permitted traffic in their respective directions.
f4 Make the approved correction supported by the failing layer’s evidence and repeat the endpoint connection test.
tb1 An endpoint connection fails, but the symptom does not identify the failing layer. Use the supplied tools and path evidence to localize the issue before making an approved correction.
tb4 Check DNS resolution and the intended endpoint address first with the supplied tools. Inspect the subnet's route-table association and destination route to a usable target, then the required protocol/port rules and response traffic. For a supplied network-ACL case, evaluate requests and responses in their respective directions because ACLs are stateless. If the evidence localizes the failure to a missing response allowance, use the approved correction for that layer rather than altering every control in the path. Repeat the endpoint connection test after correction. This example applies completed external DNS, HTTP/HTTPS and ports/firewall preparation; it does not recreate those foundations or infer a route problem from every connection error.
tb5 A permitted request direction is not enough for a stateless network ACL. Required responses need permitted traffic in their direction too. Also, an edited route table is not evidence of the used association; inspect the actual path and retest.
