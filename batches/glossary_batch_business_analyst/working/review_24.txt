FACT f1 An event is something that happens during a process and is drawn as a circle.
FACT f2 A task is an atomic activity and is drawn as a rounded rectangle.
FACT f3 A gateway controls branching and convergence of sequence flows and is drawn as a diamond.
FACT f4 Sequence flow is a solid line with a solid arrowhead indicating the order of activities within a process.
FACT f5 Message flow is a dashed line with an open arrowhead and open circle showing messages between separate participants.
FACT f6 Draw activities and appropriate events or gateways, connecting execution order with sequence flows and communication between participants with message flows.
FACT f7 Select a thin single-circle start event to show where a process starts, a thin double-circle intermediate event for something occurring between its start and end, and a thick single-circle end event to show where a process path ends.
tb1 Imagine representing a simple dispatch process: an order arrives, staff prepare it, a decision determines whether clarification is needed, and the path ends after dispatch preparation. BPMN notation gives each kind of element a distinct visual role rather than drawing every step as the same box.
tb2 An event is something that happens during a process and is drawn as a circle.
tb3 A task is an atomic activity and is drawn as a rounded rectangle. A gateway controls branching and convergence of sequence flows and is drawn as a diamond. Sequence flow is a solid line with a solid arrowhead indicating the order of activities within a process. Message flow is a dashed line with an open arrowhead and open circle showing messages between separate participants. Draw activities and appropriate events or gateways, connecting execution order with sequence flows and communication between participants with message flows. Select a thin single-circle start event to show where a process starts, a thin double-circle intermediate event for something occurring between its start and end, and a thick single-circle end event to show where a process path ends.
tb4 Draw the arrival as a thin single-circle start event and “Prepare order” as a rounded-rectangle task. Draw the branching decision as a diamond gateway. Connect execution order within the process using solid lines with solid arrowheads: these are sequence flows. If something occurs between start and end, select a thin double-circle intermediate event; mark the end of a process path with a thick single-circle end event. The example does not require every event type on every path.

Suppose dispatch sends a request to a separate participant, such as an external delivery service. Represent that communication with a dashed message flow having an open circle and open arrowhead, not with the solid sequence flow used for execution order. The diagram now distinguishes something happening, an atomic activity, routing, and communication between participants.

When reading it back, name both the element and what it represents in this process. “Diamond” describes the shape; “gateway controlling branching and convergence” explains its function. Keep the notation tied to the work rather than memorizing disconnected shapes.
tb5 A sequence flow and a message flow do different jobs. Solid sequence arrows indicate execution order within a process; dashed message flows show communication between separate participants. Start, intermediate, and end events are also distinguished by their circle outlines, not all drawn identically.
