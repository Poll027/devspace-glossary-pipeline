FACT f1 Without ORDER BY, a query’s output order is unspecified.
FACT f2 ORDER BY column ASC sorts ascending and ORDER BY column DESC sorts descending; ASC is the default.
FACT f3 Write ORDER BY first_column ASC, second_column DESC to sort by the first column and break its ties with the second.
FACT f4 When not otherwise specified, NULL values sort last for ASC and first for DESC; NULLS FIRST or NULLS LAST overrides that placement.
tb1 Suppose a reporting result contains North amount 100, South amount 100, and West amount 30. Without ORDER BY, its output order is unspecified. A stakeholder’s expectation that the biggest amounts appear first must be stated in the query.
tb2 Without ORDER BY, a query’s output order is unspecified.
tb3 ORDER BY column ASC sorts ascending and ORDER BY column DESC sorts descending; ASC is the default. Write ORDER BY first_column ASC, second_column DESC to sort by the first column and break its ties with the second. When not otherwise specified, NULL values sort last for ASC and first for DESC; NULLS FIRST or NULLS LAST overrides that placement.
tb4 Write:
SELECT Branch, Amount FROM ReportRows ORDER BY Amount DESC, Branch ASC;

Amount DESC puts larger amounts first. Branch ASC breaks the 100 tie, so the example order is North, South, West. The second sort column matters only when the first values tie. ASC is the default when a direction is omitted.

For the SQL NULL-ordering convention used here, NULL values sort last with ASC and first with DESC unless overridden. To place missing amounts last in a descending report, use:
SELECT Branch, Amount FROM ReportRows ORDER BY Amount DESC NULLS LAST, Branch ASC;

If an East row has NULL Amount, that explicit placement puts it after the non-NULL amounts. Treat the stated default as the documented SQL behavior used here, not a universal assertion about every database engine.

The practical result is an ordering rule a report reader can understand: primary comparison, direction, tie-breaker, and where missing values belong. A consistent-looking order in one earlier result is not a substitute for specifying it.
tb5 Observed output order is not a guarantee without ORDER BY. Also, descending does not automatically put NULL last under the documented default here. State NULLS FIRST or NULLS LAST when the report needs explicit placement.
