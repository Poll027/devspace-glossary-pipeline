FACT f1 A user story describes a desired outcome from a user’s perspective.
FACT f2 Write a story as “As a [persona], I [want to], [so that].” to state the user, need, and purpose.
FACT f3 Acceptance criteria describe specific conditions that must be satisfied for the story to be accepted.
FACT f4 Write each acceptance scenario on separate lines using “Given …”, “When …”, and “Then …” in that order.
FACT f5 Given sets the initial context or precondition, When describes the action or event, and Then states an expected result observable to the user or an external system.
tb1 Suppose a dispatcher needs current instructions before releasing an order. An example story is “As a dispatcher, I want to see the current delivery instructions for a selected order, so that I can prepare the correct dispatch.” The persona, need, and purpose are visible without turning the story into a technical design.
tb2 A user story describes a desired outcome from a user’s perspective.
tb3 Write a story as “As a [persona], I [want to], [so that].” to state the user, need, and purpose. Acceptance criteria describe specific conditions that must be satisfied for the story to be accepted. Write each acceptance scenario on separate lines using “Given …”, “When …”, and “Then …” in that order. Given sets the initial context or precondition, When describes the action or event, and Then states an expected result observable to the user or an external system.
tb4 The story still needs specific conditions for acceptance. One hypothetical scenario is:
Given an existing order has current delivery instructions
When the dispatcher selects that order
Then the current instructions are displayed for the dispatcher.

Given establishes the initial context, When names the action, and Then states an observable result. Keep the lines in that order. A second scenario could address an unknown order:
Given an order identifier does not exist
When the dispatcher selects that identifier
Then a not-found result is displayed.

These conditions describe what must be satisfied for this story to be accepted in the example. They do not claim the two scenarios cover every need in a real system. Discuss the relevant conditions rather than assuming the story sentence supplies them all.

The BA’s work is to connect the user-perspective outcome with specific acceptance conditions. A reader should be able to see who benefits and then identify the result to check. “The feature works correctly” would not provide the same observable expectation.
tb5 The user-story sentence and acceptance criteria are related but not interchangeable. The sentence communicates the desired user outcome; the scenarios state specific conditions for acceptance. A Then line should describe an observable result, not merely say that the action was performed.
