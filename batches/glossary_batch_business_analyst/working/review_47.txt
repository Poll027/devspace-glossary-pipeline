FACT f1 LEFT OUTER JOIN returns matching combinations and preserves each unmatched left-table row.
FACT f2 For an unmatched left row, columns from the right table are filled with NULL.
FACT f3 Write SELECT a.column_name, b.column_name FROM table_a AS a LEFT OUTER JOIN table_b AS b ON a.key_column = b.key_column; with the table to preserve on the left.
tb1 Suppose Customers contains (101, North Stores) and (102, South Stores). Orders contains (10, 101) and (11, 101). The reporting question is “List all customers, with their orders where any match.” Put Customers on the left so that unmatched customer rows are preserved.
tb2 LEFT OUTER JOIN returns matching combinations and preserves each unmatched left-table row.
tb3 For an unmatched left row, columns from the right table are filled with NULL. Write SELECT a.column_name, b.column_name FROM table_a AS a LEFT OUTER JOIN table_b AS b ON a.key_column = b.key_column; with the table to preserve on the left.
tb4 Write:
SELECT a.CustomerID, b.OrderID FROM Customers AS a LEFT OUTER JOIN Orders AS b ON a.CustomerID = b.CustomerID;

Customer 101 has two matches, producing (101, 10) and (101, 11). Customer 102 has no matching order, so it still appears, with NULL for the right-table OrderID: (102, NULL). Here a and b are the table aliases used in the supplied join pattern.

The result combines matching rows and a preserved unmatched left row. It is not limited to one output row per customer: multiple matching orders produce multiple combinations. NULL in the unmatched row represents the missing right-side fields, not an order identifier equal to zero.

The important decision is which table must remain represented when there is no match. In this example that is Customers. Reversing the table placement without changing the intended join would change which side is guaranteed preservation, so read the FROM and LEFT OUTER JOIN sides together with the business question.
tb5 “Left” refers to table placement in the query, not business importance. A left outer join preserves unmatched left rows and supplies NULL right fields for them. It still returns matching combinations rather than collapsing all matches into one row.
