tb1 Suppose OrderFact contains Amount and Quantity. A measure can total Amount while responding to current report filters. Use Modeling > New measure and enter:
TotalAmount = SUM(OrderFact[Amount])
With hypothetical North amounts 40 and 60 and South amount 30, the unfiltered total is 130 and the North-filtered total is 100.
tb2 A DAX measure calculates a result that changes with the current report filtering and selection context.
tb3 Use Modeling > New measure and enter MeasureName = SUM(TableName[NumericColumn]) to define a basic total that responds to report context. A calculated column uses a DAX expression to calculate a value for each row rather than the measure’s report-context result. Use New Column and write column_name = expression; the formula is applied across the table’s rows. In standard Import mode, calculated-column values are materialized and refreshed when the underlying data is refreshed. For a classic date-column time-intelligence calculation, use a marked date table whose Date or date/time column contains unique, nonblank dates without gaps and spans full years, including the periods being compared. Relate the date table to the metric table’s relevant date column with an active relationship so that report filters on the date table propagate to the metric’s rows. Evaluate the base total measure in the current date filter context and obtain its corresponding prior-year value with PriorYear = CALCULATE([MeasureName], SAMEPERIODLASTYEAR('Date'[Date])), which evaluates that measure with the dates shifted one year back. Compute year-over-year growth with Growth = DIVIDE([MeasureName] - [PriorYear], [PriorYear]) and format it as a percentage; without an alternate result, DIVIDE returns BLANK when the prior-year denominator is zero or blank.
tb4 A calculated column instead evaluates an expression for each row. Use New Column and enter:
DoubleQuantity = OrderFact[Quantity] * 2
Rows with quantities 2 and 3 receive 4 and 6. In standard Import mode these values are materialized and refreshed when underlying data is refreshed; do not describe them as the same report-context calculation as a measure.

For the classic date-column prior-year pattern, first use a marked date table with unique, nonblank, gap-free dates spanning full years and the compared periods. Relate it actively to the fact table’s relevant date column so date filters propagate. Then define:
PriorYear = CALCULATE([TotalAmount], SAMEPERIODLASTYEAR('Date'[Date]))
This evaluates the base measure with dates shifted one year back. Define growth with:
Growth = DIVIDE([TotalAmount] - [PriorYear], [PriorYear])
and format it as a percentage.

For an example current total of 120 and corresponding prior-year total of 100, growth is (120 − 100) / 100 = 20%. Without an alternate result, DIVIDE returns BLANK when the denominator is zero or blank. Keep the date prerequisites visible: the formula is not a substitute for the marked date table and active relationship required by this pattern.
tb5 Measures and calculated columns are not two names for the same evaluation. The measure responds to report context; the column calculates each row and, in standard Import mode, materializes values on refresh. For growth, divide the difference by prior year—not current year—and do not omit the date-table prerequisites.
