FACT f2 Choose a column type whose value category and range fit the information being stored.
FACT f3 NULL represents an unknown value, and ordinary comparisons with NULL yield unknown rather than true or false.
FACT f4 Use WHERE column_name IS NULL or WHERE column_name IS NOT NULL to test for missing values rather than = NULL.
FACT f5 COALESCE(value, replacement) returns the first non-NULL argument; use it in the SELECT list to substitute for a missing value.
FACT f6 WHERE retains only rows whose condition is true, so unknown results from NULL comparisons do not pass its filter.
tb1 Suppose Orders has Amount values 40, NULL, and 0. The missing value is unknown; it is not the same as a known zero. SQL types also distinguish categories such as integer identifiers, exact monetary values, text, dates, and Boolean values. Choose types whose categories and ranges fit what the business stores.
tb2 SQL column types distinguish integers, exact numeric values, text, dates, and Boolean values, among other types.
tb3 Choose a column type whose value category and range fit the information being stored. NULL represents an unknown value, and ordinary comparisons with NULL yield unknown rather than true or false. Use WHERE column_name IS NULL or WHERE column_name IS NOT NULL to test for missing values rather than = NULL. COALESCE(value, replacement) returns the first non-NULL argument; use it in the SELECT list to substitute for a missing value. WHERE retains only rows whose condition is true, so unknown results from NULL comparisons do not pass its filter.
tb4 To retrieve the missing-amount rows, use:
SELECT OrderID, Amount FROM Orders WHERE Amount IS NULL;
For known amounts, use IS NOT NULL instead. Do not replace that test with = NULL. Ordinary comparisons involving NULL yield unknown, and WHERE keeps only rows whose condition is true.

For a display that explicitly substitutes zero when Amount is missing, write:
SELECT OrderID, COALESCE(Amount, 0) FROM Orders;
With sample rows (10, 40), (11, NULL), and (12, 0), the displayed pairs are (10, 40), (11, 0), and (12, 0). COALESCE returns the first non-NULL argument. The display choice does not prove the original unknown amount was truly zero.

Likewise, WHERE Amount > 0 keeps the 40 row, not the NULL row or the zero row. The NULL comparison is unknown rather than false or true, and unknown does not pass WHERE. Preserving that distinction matters when interpreting what a reporting filter excluded.
tb5 NULL is an unknown value, not automatically zero or empty text. A substitution in SELECT changes the returned display value, not the business meaning of the missing source value. Use IS NULL or IS NOT NULL for missing-value tests rather than ordinary equality.
