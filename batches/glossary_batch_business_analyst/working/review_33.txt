FACT f1 A primary key constraint indicates that a column, or group of columns, can be used as a unique identifier for the rows of a table; this requires the values to be both unique and not null.
FACT f2 A table can have at most one primary key, and a primary key can span more than one column (a composite key, composed of two or more attributes).
FACT f3 Entity integrity requires that every table have a primary key, and that neither the primary key nor any part of it contain null values.
tb1 Suppose a Customer table has rows for customers 101, 102, and 103. CustomerID is a candidate for the primary key if each row’s value is unique and not null. CustomerName is less suitable in an example where two different customers share the name “North Stores”: the repeated name would not uniquely identify each row.
tb2 A primary key constraint indicates that a column, or group of columns, can be used as a unique identifier for the rows of a table; this requires the values to be both unique and not null.
tb3 A table can have at most one primary key, and a primary key can span more than one column (a composite key, composed of two or more attributes). Entity integrity requires that every table have a primary key, and that neither the primary key nor any part of it contain null values.
tb4 A table has at most one primary key, but that key can span multiple columns. Imagine a separate table of branch-specific order numbers in which order number 7 occurs at both North and South branches. The pair BranchCode and OrderNumber can form a composite key if every pair is unique and neither part is null. One key composed of two attributes is not two primary keys.

Check the sample rows deliberately. Duplicate CustomerID values violate the uniqueness requirement. A missing CustomerID violates the not-null requirement. For a composite key, check the combination for uniqueness and every component for null values. A row with a known branch but a null order number does not meet entity integrity.

The practical result is identifying the column or column group that can uniquely identify a row while meeting the stated integrity conditions. A convenient-looking label is not enough: the actual values must satisfy uniqueness and non-null requirements.
tb5 Unique is not the whole primary-key rule: values must also be not null, and no part of a composite primary key may be null. A composite key is one primary key spanning columns, not permission to assign several primary keys to a table.
