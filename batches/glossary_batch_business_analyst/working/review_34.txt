FACT f1 A foreign key constraint specifies that the values in a column (or group of columns) of one table must match values appearing in some row of another, referenced table.
FACT f2 A null foreign key value also satisfies referential integrity; a non-null one must match an existing primary key value in the referenced table.
FACT f3 A row whose foreign key value is not found in the referenced table is called an orphan record; referential integrity is what prevents these.

tb2 A foreign key constraint specifies that the values in a column (or group of columns) of one table must match values appearing in some row of another, referenced table.
tb3 A null foreign key value also satisfies referential integrity; a non-null one must match an existing primary key value in the referenced table. A row whose foreign key value is not found in the referenced table is called an orphan record; referential integrity is what prevents these.
tb4 The foreign-key constraint requires non-null referencing values to match a value in the referenced table. A row with 999 would be an orphan record if that value is absent from Customer. Referential integrity prevents that unmatched reference rather than making up a new customer to satisfy it.

A null foreign-key value also satisfies referential integrity under this referential-integrity rule. That is different from primary-key rules, where null is not allowed. For the exercise, distinguish three cases: matching 101, unmatched non-null 999, and null. Do not describe all three as simply “valid customer values”: null represents no known referenced value here, while 101 matches an existing customer.

A foreign key can also use a group of columns when the reference requires it. The learner’s immediate task is to check whether the referencing value or values match the required referenced row, while preserving the stated null exception. Keep the example about references and integrity rather than adding deletion or update behavior that has not been established.
tb5 The foreign-key null rule differs from the primary-key rule. In this brief, null satisfies referential integrity; a non-null value must match. Do not treat an unmatched non-null value as an acceptable unknown.
