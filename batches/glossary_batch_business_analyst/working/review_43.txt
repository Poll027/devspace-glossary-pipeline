FACT f1 For each row of T1, an INNER JOIN produces a joined row for each row of T2 that satisfies the join condition; rows from either table with no match are dropped.
FACT f2 The join condition is written in an ON clause, a boolean expression of the same kind used in a WHERE clause, or as a USING clause when both tables use the same column name.
FACT f3 INNER is the default kind of join; writing JOIN alone (without CROSS, LEFT, RIGHT, or FULL) means an INNER JOIN.
tb1 Imagine Customers contains (101, North Stores) and (102, South Stores), while Orders contains order 10 for customer 101 and order 11 for customer 999. A report needs an order identifier paired with its matching customer name.
tb2 For each row of T1, an INNER JOIN produces a joined row for each row of T2 that satisfies the join condition; rows from either table with no match are dropped.
tb3 The join condition is written in an ON clause, a boolean expression of the same kind used in a WHERE clause, or as a USING clause when both tables use the same column name. INNER is the default kind of join; writing JOIN alone (without CROSS, LEFT, RIGHT, or FULL) means an INNER JOIN.
tb4 Write:
SELECT Orders.OrderID, Customers.Name FROM Orders INNER JOIN Customers ON Orders.CustomerID = Customers.CustomerID;

The join condition compares the two customer identifiers. Order 10 matches customer 101, producing (10, North Stores). Order 11 has no matching customer row in this deliberately unmatched reporting example, so it is dropped. Customer 102 has no matching order and is also dropped. The unmatched value illustrates join behavior; it is not a valid foreign-key example under an enforced matching constraint.

An INNER JOIN produces a joined row for every satisfying pair, not simply one result for each input table. If multiple rows on the other side satisfy the condition, each matching pair contributes a joined row. The condition can be expressed with ON, or USING when both tables use the same column name. JOIN by itself, without a different join kind, means INNER JOIN.

The practical reporting question is therefore which matches the condition creates and which rows lack matches. Do that reasoning before assuming the result includes every customer or every order.
tb5 An inner join does not preserve unmatched rows. Also, “one match per row” is not its general rule: each satisfying pair produces a joined row. In this sample there is one matching pair, but that is a property of the data, not a universal join limit.
