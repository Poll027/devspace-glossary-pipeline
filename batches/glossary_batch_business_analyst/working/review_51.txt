FACT f1 For a top-N report, compute the metric per group, order it descending, and limit the output: SELECT group_column, SUM(value_column) AS total FROM table_name GROUP BY group_column ORDER BY total DESC, group_column LIMIT n;
FACT f2 A predictable limited result requires an ordering that determines which rows come first.
FACT f3 LAG(metric) OVER (ORDER BY period_column) retrieves the previous row’s metric for an ordered period comparison; the first row has NULL by default.
FACT f4 SUM(metric) OVER (ORDER BY period_column ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) computes an ordered running total over the rows through the current row.
tb1 Suppose hypothetical Orders totals are North 100, South 80, and West 80. To report the top two branches, compute each group’s metric, sort it descending, include a tie-breaker, and limit the output:
SELECT Branch, SUM(Amount) AS total FROM Orders GROUP BY Branch ORDER BY total DESC, Branch LIMIT 2;
The result is North 100 and South 80. The Branch ordering decides between the tied 80 totals; the limit alone would not establish a predictable top-two result.
tb2 For a top-N report, compute the metric per group, order it descending, and limit the output: SELECT group_column, SUM(value_column) AS total FROM table_name GROUP BY group_column ORDER BY total DESC, group_column LIMIT n;
tb3 A predictable limited result requires an ordering that determines which rows come first. LAG(metric) OVER (ORDER BY period_column) retrieves the previous row’s metric for an ordered period comparison; the first row has NULL by default. SUM(metric) OVER (ORDER BY period_column ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) computes an ordered running total over the rows through the current row.
tb4 For period comparison, suppose PeriodMetrics contains unique periods 1, 2, and 3 with Metric 10, 15, and 8. Write:
SELECT Period, Metric, LAG(Metric) OVER (ORDER BY Period) FROM PeriodMetrics ORDER BY Period;
The previous-row values are NULL, 10, and 15. The first row has no previous row and defaults to NULL.

For a running total, write:
SELECT Period, SUM(Metric) OVER (ORDER BY Period ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) FROM PeriodMetrics ORDER BY Period;
The totals are 10, 25, and 33. The frame runs from the first row through the current row. These are three different reporting patterns: ranked limited output, previous-row comparison, and cumulative total. Keep the unique period ordering in this example visible rather than implying a previous-row value is always the previous calendar period when data has gaps.
tb5 LIMIT alone does not determine which rows come first. LAG retrieves the previous ordered row, while the specified SUM frame accumulates rows through the current one. Do not describe these distinct calculations as if they all simply return a grouped total.
