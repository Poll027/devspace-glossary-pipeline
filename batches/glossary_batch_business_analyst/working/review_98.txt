tb4 For this hypothetical arrangement, define the shared business calculation as a measure in the common model. Build both reports from that model when they need the same calculation. One report may focus on branches and another on customers while using the shared calculation definition.

Connect a new report to the existing shared semantic model. Building content on it requires Build permission, so do not assume access to a finished report automatically grants authority to build new content from its model.

The useful mental model is shared data-model logic supporting multiple reports, rather than every report independently recreating the same business calculation. The example does not promise every report will display the same result under different filters; it is the common calculation definition that is reused. Keep the distinction between shared model, report, and required Build permission clear.
tb5 Sharing a calculation definition does not mean every differently filtered report displays an identical number. Reports reuse model logic. Also, building new content on the shared model requires Build permission; do not treat mere report access as that permission.
